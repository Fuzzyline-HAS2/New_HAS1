# 조립 전 검증과 7대 설치

2026-09-17 기준. 현재 G1P1 테스트 한 쌍은 GPIO1 수정본 USB 설치, UART 응답, 리셋 펄스 후 Beetle 재부팅·통신 복구를 확인했다. **실제 두 보드 OTA와 Telnet 접속은 아직 미검증**이다. 세부 실측은 [검증 기록](VALIDATION.md)을 따른다. 아래 미완료 항목은 실행·통과를 의미하지 않는다.

## 1. 현재 한 쌍으로 OTA·Telnet 실증 — 대기

- [ ] 서버의 장치 등록과 유효한 상태 응답을 확인하고, 게임 진행 중이 아닌 허용 페이즈에서 시작한다. 두 보드의 현재 펌웨어·파티션·boot ID와 사용할 서명 산출물의 출처·해시를 기록한다.
- [ ] [빌드·릴리즈 규칙](BUILD.md)에 맞는 실제 배포 키와 동일 파티션의 산출물로 **Beetle 업데이트 → 새 부팅·목표 버전 확인 → TTGO 업데이트**를 실증한다. `flashing` 표시나 동일 버전 `skipped`만으로 실제 설치 성공을 판정하지 않는다.
- [ ] TTGO 재접속 후 양쪽 실행 버전과 UART 응답을 확인한다. 한쪽만 변경되거나 실패하면 결과를 기록하고 다음 기기로 확대하지 않는다.
- [ ] TTGO Telnet에서 상태·일치 PING 응답과 Beetle BOOT/OTA 로그를 확인한다. 재접속, Beetle USB 미연결, 반복 PING 중 BOOT 중복 억제, 로그 출력 중 UART 응답을 확인한다. 새 진단 펌웨어 설치 전 로그 부재를 실패로 오판하지 않는다.
- [ ] 서명 오류·없는 버전·통신 단절의 실패 처리와 지원되는 보관 버전의 롤백을 별도 기록한다. 기존 USB 리셋 실측만으로 WDT reset cause 판독이나 OTA 복구까지 통과 처리하지 않는다.

## 2. G1P1~G1P7, 총 7대 초기 USB 설치 — 대기

위 한 쌍의 실증 결과를 확인한 뒤 확정한 이미지로 진행한다. 기존 G1P1을 포함해 **총 7대**이며 각 장치는 TTGO와 Beetle 한 쌍이다. 실물 라벨과 서버 장치명을 대조하고, MAC/IP·개별 백업·원본 로그는 로컬 장치 목록에만 보관한다. 공개 문서와 PR에는 해당 주소 목록이나 비밀값을 넣지 않는다.

- [ ] 장치별 기존 상태·필요한 플래시 영역을 백업하고, 배선·공통 GND·전원·모터 드라이버를 확인한다. 리셋 연결은 TTGO GPIO12 → Beetle GPIO1이다.
- [ ] 두 보드의 애플리케이션은 각각 GitHub Actions Release에서 내려받아 서명을 검증한 `update.bin`과 동일한 바이트로 설치하고, `min_spiffs` 파티션을 사용한다. compile-only 이미지 사용을 차단하고 업로드 네 영역 해시 검증, 펌웨어·파티션 버전, 부팅 안정성을 장치별 기록한다.
- [ ] 각 장치의 Wi-Fi·서버 등록, UART 일치 PING, 리셋 후 새 boot ID와 통신 복구, Telnet 재접속을 확인한다. 한 대의 결과를 나머지 장치에 적용하지 않는다.
- [ ] 칩·버튼·LED·진동을 확인하고, 실제 비콘 매핑과 배터리 ADC 배선·분압비·멀티미터 보정을 검증한다. 배터리 측정 기본 비활성 상태를 측정 완료로 기록하지 않는다.
- [ ] 각 장치의 필수 항목을 통과한 뒤 최종 조립한다. 실패·기획 차이는 재현 조건과 기대 동작을 적어 별도 서브아이템으로 분리하며, 미해결 장치는 구분해 둔다.

## 3. PR·Actions·운영 OTA — 대기

- [ ] 공개 PR에서 소스·문서·서명/보관 정책을 독립 검토하고, host/Python 테스트 및 TTGO 본게임·훈련·Beetle 컴파일 결과를 확인한다. [서버 계약](SERVER_CONTRACT.md)의 미해결 항목과 실제 게임 사이클 검증 결과도 명시한다.
- [ ] 워크플로 변경을 기본 브랜치에 반영한 뒤 기존 `Deploy Firmware` 규칙으로 두 대상을 하나씩 배포한다. 정수 버전은 CI가 증가시키며, 고정 릴리즈와 버전 보관 릴리즈의 자산·서명·출처를 각각 확인한다. 여러 실행을 동시에 대기열에 넣지 않는다.
- [ ] 운영 OTA는 먼저 한 쌍에 적용해 목표 버전·새 부팅·재연결·기본 동작을 확인한 뒤 나머지 6대로 확대한다. 두 보드 업데이트는 원자적이지 않으므로 부분 성공 시 각 보드의 실행 버전을 확인하고 복구한다.
- [ ] 최종 설치 버전과 검증 일자를 로컬 장치 목록에 갱신하고, 공개 검증 기록에는 주소·비밀값을 제거한 결과만 남긴다. 게시·설치·실측 여부를 구분해 완료 표시한다.
