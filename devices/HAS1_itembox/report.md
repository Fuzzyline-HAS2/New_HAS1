## 1. GAME SYSTEM (상태 머신)

### 구조

```
GAME_WAIT_TAG ──(NFC 태그)──> GAME_PUZZLE ──(정답 3개)──> GAME_SOLVED ──(재태그: 닫기)──> GAME_WAIT_TAG
                                  ⇅ (태그 이탈 / 재태그)
                             GAME_PAUSED ──(30초 방치)──> GAME_WAIT_TAG (리셋)
```

- 상태 전환은 `ChangeGameState()` 한 곳에서만 수행. 각 상태의 진입 처리(LED 색, 타이머/플래그 초기화)를 전환 함수에 집중시켜 **상태 간 의존성 제거** (전환 지점마다 진입 코드를 복사하다 누락되는 버그 원천 차단)
- 게임 규칙: 카드를 리더에 **올려둔 상태**로 퍼즐 진행. 태그 이탈 시 일시정지(진행 상황 유지), 재태그 시 이어서 진행, 30초 방치 시 처음부터
- 정답 3개(엔코더 위치 13/43/21, ±2 허용) 완료 → 박스 열림 → **카드를 뗐다가 재태그**해야 닫힘

### 발견·해결한 이슈

| 증상 | 원인 | 해결 |
|---|---|---|
| 박스가 열리자마자 닫히는 등 무규칙 토글 | 퍼즐 내내 올려둔 카드를 "닫기 태그"로 오인 → 닫은 뒤엔 또 "새 게임 태그"로 오인 | 카드 뗌 확인(`waitTagRelease`, 0.7초 연속 미감지) 도입 — 동작마다 뗐다 재태그 필수 |
| 태그 직후 즉시 오탐 일시정지 | NFC 태그는 읽힌 직후 잠시 감지에 응답하지 않음. 확인 주기 200ms × 타임아웃 500ms = 기회 2번뿐 | 타임아웃 2000ms에서 오탐 없음 확인. **현재 반응성 우선으로 500ms 유지 중 — 오탐 재발 시 이 값을 올릴 것** |
| 퍼즐 중 네오픽셀/엔코더 반응 렉 | PN532 통신(수십 ms)을 매 loop 수행 | 태그 확인을 200ms 주기로 제한 |

### 상태별 네오픽셀

| 상태 | 육각 (PN532 쪽) | 엔코더 링 |
|---|---|---|
| 대기 | 흰색 | 흰색 |
| 퍼즐 | **파란색** | 파란 배경(단계별 밝기) + 현재 위치 빨강 1픽셀 |
| 일시정지 | 노란색 | 노란색 |
| 정답/오답 순간 | - | 초록/빨강 5회 점멸 (2.5초, 연출 중 입력 무시) |
| 해결(박스 열림) | 초록색 | 초록색 |

## 2. LINER MOTOR (BTS7960)

### 구현

- LEDC PWM 5kHz / 8비트, 듀티 255(최대) 사용
- 열기: `boxOpen()` → millis 기반 4초 구동 후 `boxUpdate()`가 자동 정지 (논블로킹)
- 닫기: `boxClose()` → 마이크로 스위치(GPIO36, 외부 풀다운) 눌림 감지 시 정지
- 안전 규칙: 방향 전환 시 반대쪽 PWM을 먼저 0으로 끈 후 출력 (RPWM/LPWM 동시 구동 방지)

### 발견·해결한 이슈

| 증상 | 원인 | 해결 |
|---|---|---|
| 절반만 닫히고 멈춤 | 듀티 128(50%)로는 부하를 못 이겨 스톨 | 듀티 255(최대)로 상향 |
| 열기 명령에 완전 무음 무반응 | 모터 방향이 리버스 배선 (열기 방향이 이미 행정 끝 → 액추에이터 내장 리미트가 차단) | `boxOpen`/`boxClose`의 RPWM/LPWM 역할 스왑 |
| 닫는 중 스위치가 안 눌렸는데 1초 만에 정지 | 모터 구동 노이즈가 스위치 라인(GPIO36)에 유도돼 순간 HIGH 오탐 | 50ms 연속 HIGH여야 눌림 인정하는 디바운스 추가 |

권장 하드웨어 보강: 스위치 배선을 모터 전원선과 분리, GPIO36-GND에 0.1µF 커패시터 (소프트웨어 디바운스로 현재 동작은 정상)

## 3. ENCODER

### 구현

- ESP32 PCNT 하드웨어 카운터(ESP32Encoder 라이브러리) — 인터럽트/CPU 부담 없이 하드웨어가 직접 카운트
- `attachFullQuad` + 카운트/4 = 한 틱당 1 (범위 0~95, 클램프 시 `setCount`로 하드웨어 카운트도 고정)

### 발견·해결한 이슈

| 증상 | 원인 | 해결 |
|---|---|---|
| 반응이 절반으로 죽음 (두 칸 돌려야 1 증가) | `attachSingleEdge`는 쿼드러처 한 주기당 1카운트인데, 사용 중인 엔코더는 한 주기에 디텐트 2개인 타입 | `attachFullQuad` + /4 (구형 프로젝트와 동일 방식)로 복귀 |
| 회전 방향 리버스 | 하드웨어 A/B 배선이 반대 | attach 시 A/B 핀 순서 스왑으로 해결 |

## 4. VIBRATION MOTOR (TB6612FNG)

### 구현

- PWMA(GPIO14) 단일 채널로 세기만 제어 (AIN1→3.3V, AIN2→GND, STBY→3.3V 고정 배선, 방향 고정)
- 퍼즐 힌트: 정답과의 거리에 따라 4단계 세기 + 무진동 — `{255, 190, 150, 110, 0}` (가까울수록 강함)

### 5차 테스트 결과: 보드 리셋 시마다 1~2초 진동 울림

GPIO14는 ESP32의 JTAG 디버그 핀(MTMS)이라서, 리셋 순간부터 부트로더가 도는 동안 칩이 이 핀에 **내부 풀업을 자동으로 켠다.** ROM 부트로더 → 2차 부트로더 → 코어 초기화를 거쳐 `vibration_motor_Init()`의 `ledcWrite(0)`이 실행되기까지 수백 ms가 걸리고, 그동안 TB6612가 HIGH를 받아 진동이 울리는 것. **코드 실행 이전 구간의 현상이라 소프트웨어로는 해결 불가.**

- 완화 조치(적용됨): `setup()`에서 `vibration_motor_Init()`을 최우선 호출해 울림 시간 최소화
- 근본 해결(선택): ① PWMA를 부팅 중 조용한 핀(GPIO21/22/26)으로 이동 ② GPIO14-GND에 10kΩ 풀다운 저항

### 추가 정보: 진동 세기가 약한 원인 — 정격 전압 차이

이전(3호점) 아이템박스 진동모터 정격 전압은 5V(추정)였으나, **리뉴얼 1호점 진동모터는 정격 7V.** 같은 세기 숫자를 넣어도 진동이 약하게 울린다.

- 모터가 받는 평균 전압 = VM 공급 전압 × (듀티/255). VM이 5V라면 최대 듀티(255)로도 5V — **7V 정격 모터 기준 약 70% 출력**이 상한
- 대응 방안: ① TB6612 VM에 7V 이상 전원 공급 (VM 최대 15V까지 허용) ② 현 전원 유지 시 세기 테이블을 최대치 위주로 재튜닝 (현재 최강 단계는 이미 255라 추가 상향 불가)
