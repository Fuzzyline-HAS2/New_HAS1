# 발전기 텔넷 로그 경로

이 변경은 로그 전달만 보완합니다. 게임 로직, 펌웨어 버전, OTA 배포 설정은 바꾸지 않습니다. 변경 소스를 빌드/설치하기 전에는 현장 발전기의 동작도 바뀌지 않습니다.

## 전달하는 출력

- 스케치의 `Serial.print/println/printf`는 기존 USB UART 출력과 최근 RAM 이력에 기록합니다.
- `Serial.begin()` 직후 `has2wifi.SetDebugPrint(&DebugSerial)`를 연결하여 HAS2_Wifi의 동기/비동기 디버그 출력도 같은 경로로 받습니다. 라이브러리에 원래 없는 로그를 생성하거나 통신 동작을 바꾸지는 않습니다.
- `esp_log_set_vprintf`를 통과하는 ESP-IDF 로그를 RAM에 복사하고, 이전 출력 콜백도 호출해 기존 UART 로그를 유지합니다. 한 번의 ESP-IDF 포맷 출력은 텔넷 이력에서 최대 511바이트까지 보존하고 잘림 표시를 붙입니다. 기존 UART 출력은 이 제한을 적용하지 않습니다.
- Wi-Fi/텔넷 초기화 전의 위 로그도 **최근 8KiB** 범위에서는 접속 후 재생합니다. 미완성 줄도 바이트 이력에 포함합니다. 버퍼가 차면 오래된 내용부터 덮어쓰므로 전체 부팅 로그를 보장하지 않습니다.
- `CrashReportInit()`에서 만든 직전 리셋 요약은 URL 전송용으로 변형되기 전에 별도 고정 RAM에 복사합니다. 접속마다 `[retained reset report]`로 출력하므로 최근 이력이 덮어써져도 이 요약은 남습니다. 원본 리셋 진단 자체의 RTC/NVS 복원 정확도는 기존 구현과 같습니다.
- 접속 때 기존 펌웨어/장치/MAC/IP/힙/BLE 상태 스냅샷을 유지하고, 과거 로그 시작/종료를 표시한 후 현재 출력을 이어 보냅니다. 과거 로그에 붙는 PC 수집 시각은 원래 발생 시각이 아니라 재접속해서 받은 시각입니다.

## 느린 수집기 처리

`Serial.write()`와 ESP-IDF 로그 콜백은 TCP에 직접 쓰지 않습니다. 고정 크기 RAM 이력을 짧은 critical section으로 보호하고, UART/포맷/네트워크 작업은 lock 밖에서 수행합니다. HAS2_Wifi 작업 태스크와 다른 ESP-IDF 태스크에서 동시에 로그를 남겨도 이력 메모리가 손상되지 않도록 합니다. 여러 태스크의 문장 전체를 원자적으로 묶는 기능은 아니므로 출력 조각이 섞일 수 있습니다. ISR에서 호출하는 로그 함수는 지원하지 않습니다.

`TelnetRun()`의 이력 전송 함수 `TelnetDrain()`은 한 번에 최대 네 번, 각 256바이트의 `send(..., MSG_DONTWAIT)`만 시도합니다. 두 번째 클라이언트의 접속 거절 응답은 별도로 최대 한 번 전송합니다. 부분 전송은 실제 전송한 만큼만 진행하고, 소켓이 막히면 다음 게임 루프로 넘깁니다. 수집기가 느려 미전송 이력이 덮어써지면 `[Telnet] log overflow: ... bytes skipped`를 보냅니다. 이때 다음 줄/UTF-8 문자의 시작이 잘려 있을 수 있습니다.

한 장치에는 한 클라이언트만 접속합니다. 두 번째 연결은 기존 연결을 끊지 않고 `Telnet already connected.` 응답을 최선의 노력으로 보낸 뒤 닫습니다. 입력 데이터는 명령으로 처리하지 않으며 루프당 최대 64바이트만 버립니다. 기존 PC→UART 문자 전달은 제거하여 원격 입력이 로그/게임 루프를 지연시키지 않게 했습니다.

## 한계

- **모든 UART 출력의 100% 복제는 아닙니다.** ROM 부팅 메시지, 패닉 핸들러의 직접 출력, `ets_printf`/`esp_rom_printf`, 별도 라이브러리의 직접 `Serial0`/UART 호출, 기본 Arduino HAL `log_printf` 경로는 이 후킹을 우회할 수 있습니다. 컴파일/런타임 로그 레벨로 제거된 로그도 복원하지 못합니다.
- Wi-Fi 연결/텔넷 서버 초기화까지 진행하지 못하면 접속할 수 없습니다. RAM 이력은 재부팅/전원 차단으로 사라집니다. 기존 리셋 요약 외에 이전 부팅의 전체 로그를 영구 저장하지 않습니다.
- TCP 전송은 Arduino 메인 루프에서 진행합니다. 게임/통신 코드가 메인 루프를 오래 막으면 RAM에 쌓인 마지막 출력도 그동안 전송되지 않을 수 있습니다. 이 변경이 루프 정체 자체를 고치거나 정체 직전 모든 로그 전달을 보장하지는 않습니다.
- 기존 UART 출력 자체는 그대로입니다. 이 변경이 제거하는 대기는 텔넷 소켓 쓰기 대기이며 UART나 기존 게임/HTTP 함수의 블로킹 동작까지 제거하지 않습니다.
- 버퍼 초과 및 전원 차단 등으로 일부 로그가 유실될 수 있습니다. 로그가 없다는 사실만으로 코드 미실행/MCU 정지/전기적 원인을 단정하지 않습니다.

## 확인

```sh
python3 devices/HAS1_generator/tests/run_telnet_tests.py
python3 devices/HAS1_generator/tests/run_tagger_tests.py
```

텔넷 테스트는 실제 소스의 송신/로그 콜백 함수를 추출해 호스트 C++ 및 ASan/UBSan으로 부분 전송, 송신 예산, EAGAIN, 이력 초과, 리셋 원문 보존 등을 검사합니다. 하드웨어 Wi-Fi, 실제 FreeRTOS 동시 실행, 전원 장애를 재현하는 테스트는 아닙니다. 실제 펌웨어 빌드와 현장 수집 시험은 별도로 필요합니다.
