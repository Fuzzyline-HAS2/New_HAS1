# IoT 글러브 vibe 연출 명령(10~17) 설계

- 작성: 2026-09-19
- 대상: `devices/iotglove` (TTGO 펌웨어). Beetle 보드는 변경 없음
- 결과 버전: iotglove **v8** (현장 v6 → v8, v7 밝기 통일 포함)
- Notion 작업 카드: 「IOT 글러브 연출 진동 기능 만들기」(기획 팀 / 1호점 리뉴얼 SW 작업 정리)

## 1. 배경과 목적

현재 글러브 진동은 세 가지뿐이다.

| 종류 | 발동 조건 | 위치 |
|---|---|---|
| 근접 펄스 (vibe 1/3) | `game_state=activate` + `role=player` + 서버 15초·위치 5초 freshness | `feedback.h:76-80` |
| 상태전환 패턴 | setting/ready/player/ghost/tagger/ended 진입 순간 1회 | `feedback_config.h:17-24` |
| 칩 제거/발견 이벤트 | 이벤트 발생 시 | `feedback.h:59-66` |

운영자가 원하는 시점에 글러브를 울리거나 멈출 수단이 없다. 서버 `vibe` 필드에
명령값 10~17을 추가해 상태·역할과 무관하게 연출 진동을 제어할 수 있게 한다.

### 비범위
- 서버 측 구현(운영 UI, 재계산 보류 로직). 계약만 정의한다
- Beetle 펌웨어, LED 표시, 진동 세기(모터는 ON/OFF 디지털 출력)
- 명령 실행 결과를 서버에 보고하는 ACK

## 2. 동작 규칙

| 서버 `vibe` | 동작 | 유형 |
|---|---|---|
| 0 | 근접 진동 없음 (기존) | 유지형 |
| 1 | 인접 방: 2초마다 100ms 펄스 (기존) | 유지형 |
| 3 | 같은 방: 1초에 100ms 펄스 2번 (기존) | 유지형 |
| 2, 4~9 | 무동작 — 0과 동일 취급 | — |
| **10** | 음소거 — 유지되는 동안 모터 절대 OFF (근접·상태전환·칩 이벤트 전부 침묵) | 유지형 |
| **11** | 연속 ON — 유지되는 동안 모터 계속 ON | 유지형 |
| **12 / 13 / 14** | 짧은 진동 200ms × 1 / 2 / 3회, 간격 200ms (총 0.2 / 0.6 / 1.0초) | 1회(엣지) |
| **15 / 16 / 17** | 긴 진동 600ms × 1 / 2 / 3회, 간격 200ms (총 0.6 / 1.4 / 2.2초) | 1회(엣지) |
| 18 이상, 음수, 누락 | 스냅샷 거부 (기존 동작 유지 — 글러브는 미동기화 상태가 됨) | — |

- **동작 범위**: 유효한 서버 스냅샷이면 `game_state`·`device_state`·`role`과 무관하게 즉시 반응한다.
  유일한 예외는 기존과 같은 OTA·리셋 중 모터 강제 OFF(`iotglove.cpp:455`).
- 명령 진동 길이는 상태전환 진동(150/300/100ms)과 **별도 설정값**으로 둔다.

### 2-1. 1회 재생(12~17)의 트리거 규칙

`vibe`는 1초(`kPollMs=1000`, `wifi.cpp:24`)마다 폴링되는 유지형 값이다. 12~17은 **값이 직전과 다른 값으로
바뀐 순간** 한 번만 재생된다.

- `0 → 12`: 짧은 진동 1회. 이후 12가 계속 와도 재생하지 않는다
- `12 → 13`: 진행 중 패턴을 끊고 2회 패턴을 시작한다
- `12 → 0 → 12`: 다시 재생한다. 같은 명령을 반복하려면 서버가 다른 값(보통 0)을 거쳐야 한다
- 명령값이 유지되는 동안은 값이 1/3이 아니므로 **근접 진동이 멈춘다**. 명령 후 서버가 근접 값(0/1/3)으로
  되돌려야 근접 진동이 복귀한다

### 2-2. 서버 계약

1. 각 vibe 값은 **최소 2초 유지**한다 — 1초 폴링 한 번을 놓쳐도 글러브가 관측할 수 있게
2. 현재 서버는 글러브의 `location` 보고로 `vibe`를 0/1/3으로 **재계산**한다(`docs/SERVER_CONTRACT.md:59`).
   **명령값(10~17)이 유지되는 동안 재계산이 이를 덮어쓰지 않도록** 서버가 보장해야 한다. 펌웨어로는 해결할 수 없다
3. 명령이 끝나면 서버가 근접 값으로 복귀시킨다
4. 값 범위는 0~17 정수. 그 밖은 스냅샷 거부이므로 보내지 않는다

## 3. 우선순위와 예외

### 3-1. 우선순위 (높음 → 낮음)

| 순위 | 진동 | 규칙 |
|---|---|---|
| 1 | 10 음소거 | 유지 중 전부 OFF. 진입 시 진행 중 패턴 취소 |
| 2 | 11 연속 ON | 유지 중 ON. 진입 시 진행 중 패턴 취소(해제 후 옛 패턴이 이어 울리지 않게) |
| 3 | 칩 제거/발견 이벤트 | 명령 패턴 진행 중이어도 끊고 재생 — 게임 필수 신호. 단 10 중엔 침묵 |
| 4 | 명령 패턴 12~17 | 상태전환 패턴을 덮는다. 진행 중 상태전환이 와도 끊기지 않는다 |
| 5 | 상태전환 패턴 | 기존 그대로 |
| 6 | 근접 펄스 1/3 | 기존 그대로. 어떤 패턴이든 진행 중이면 그 OFF 구간에도 침묵(기존 규칙) |

칩 이벤트가 명령을 이기는 이유: 칩 제거는 플레이어가 놓치면 안 되는 신호이고, 운영자 연출은 다시 보낼 수 있다.

### 3-2. 예외 처리

- **스냅샷 무효**(`stateValid=false`; `publishInvalid`가 `vibe=0`을 발행, `wifi.cpp:135-141`): 기존처럼 패턴 취소·모터 OFF.
  이때 `lastVibe_`는 **갱신하지 않는다** → `12 → (순간 오류) → 12`에서 두 번 울리지 않는다
- **OTA/리셋 중**(`suppressed`): 모터 OFF(기존). 유효 스냅샷의 vibe는 **소비만** 한다(`lastVibe_` 갱신, 재생 없음)
  → OTA가 끝난 뒤 늦게 울리지 않는다
- `12 → 13 → 12` 왕복: 전환마다 재생(엣지 규칙)
- **부팅·재동기화 직후(baseline: 첫 동기화 또는 연결 epoch 변경)**: 기존처럼 모든 패턴을 취소하고, 그 스냅샷의
  명령값은 **소비만** 한다(`lastVibe_ = vibe`, 재생 없음) → OTA 재부팅 뒤 서버가 12를 치우지 않았어도 울리지 않는다
- 11 장시간 유지: 모터 연속 구동으로 발열·배터리 소모. 펌웨어 제한은 두지 않고 운영 주의사항으로 문서화
- 4~9: 0 취급. LED 표시는 vibe와 무관하므로 변경 없음

## 4. 내부 구조 — 변경 파일

### `feedback_config.h`
- `Schedule`을 주기형 `{ onMs, gapMs, pulses, total }`로 일반화한다.
  `motorOn(s, t)` = `t < total && t % (onMs + gapMs) < onMs`
- 기존 `schedule(Pattern, Settings)`는 그대로 Short1/Long1/Short2를 만든다.
  Short2 = on150·gap100·pulses2·total400으로 기존 경계값과 동일
- 명령용 빌더 `pulses(onMs, gapMs, count)` 추가
- `Settings`에 `commandShortMs = 200`, `commandLongMs = 600`, `commandGapMs = 200` 추가
- `firstOn/gap/secondOn`은 이 파일 내부에서만 쓰이므로 다른 파일·테스트 수정 없음

### `feedback.h`
- `Source::Command` 추가, `uint8_t lastVibe_ = 0` 추가. `update()` 시그니처는 변경 없음
- `update()` 순서:
  1. LED 표시 계산(기존)
  2. 무효/억제 조기 반환 — 무효면 `lastVibe_` 유지, 억제면 `lastVibe_ = vibe`로 소비
  3. `vibe == 10`: `cancel()`, `lastVibe_ = vibe`, 모터 OFF로 반환
  4. `vibe == 11`: 진입 시 `cancel()`, `lastVibe_ = vibe`, 모터 ON으로 반환
  5. `vibe`가 12~17이고 `vibe != lastVibe_`: `start(pulses(...), Source::Command, now)`. `lastVibe_ = vibe`
  6. 기존 이벤트/상태 로직 — 칩 이벤트는 `Source::Command`를 끊고 시작(기존 무조건 `start`),
     상태전환의 `source_ != Source::Event` 검사에 `Command`를 추가해 명령을 끊지 못하게 함.
     정지 상태(setting/ready/ended) 전환 시의 `cancel()`(`feedback.h:56-57`)도 `source_ == Source::Command`면 건너뜀.
     단 baseline(첫 동기화·epoch 변경)의 `cancel()`은 기존대로 명령 포함 전부 취소하고, 이때 5번의 엣지 시작은
     하지 않고 `lastVibe_ = vibe`로 소비만 한다
  7. 모터 계산(기존) — `pattern_.total`이 있으면 패턴, 없으면 근접 펄스

### `wifi.cpp:98`
- `number(my["vibe"], 0, 3, vibe)` → `number(my["vibe"], 0, 17, vibe)`. 거부 의미는 유지

### `game_state.h`
- `ServerSnapshot.vibe`는 `uint8_t` 그대로(17 ≤ 255). 변경 없음
